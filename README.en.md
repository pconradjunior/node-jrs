# json-rest-server

A fully functional RESTful server based on JSON, for development and
prototyping. **Node.js port of the
[`json_rest_server`](https://github.com/rodrigorahman/json_rest_server) (Dart)**,
keeping full drop-in compatibility with the original's `config.yaml` /
`database.json` format.

Works as an npm package **and** as a standalone cross-platform executable
(built with Node SEA).

## Requirements
- Node.js >= 20

## Install
```bash
npm install -g json-rest-server
```

## Quick start
```bash
# 1. Generate config.yaml, database.json and the storage/ folder
json-rest-server create

# 2. Start the server (defaults to http://0.0.0.0:8080)
json-rest-server run
# or just: json-rest-server
```

- `create` generates a `database.json` with sample collections: `users`,
  `adm_users`, `categories` and `products`.
- **Storage route:** files uploaded via `POST /uploads` are stored and served
  at `GET /storage/<filename>`.
- **Broadcast:** with `enableSocket: true`, write operations (POST/PUT/PATCH/DELETE)
  are pushed as `{channel, table, data}` over TCP (default `:8081`) and/or WebSocket.

## CLI
| Command | Description |
|---|---|
| `create` | Generate initial `config.yaml`, `database.json` and `storage/` |
| `run` | Start the server |
| `--debug` / `-d` | Enable verbose debug logging (e.g. auth, persistence, socket events) |

## Request logging

While the server is running, every endpoint call is logged with the HTTP method,
path, status code and duration — matching the original Dart server's always-on
`logRequests()` behavior:

```
[JSON Go Server] Server started on http://127.0.0.1:8080
[POST] /auth -> 200 (3ms)
[GET] /products -> 200 (1ms)
[GET] /products/999 -> 404 (0ms)
```

Request logging is **enabled by default** (no flag needed). The `--debug`/`-d`
flag only adds more verbose lines (auth, persistence, socket events); it doesn't
control request logging. If you need to silence it, the logger supports a
`quiet` mode — see `src/util/logger.js`.

## Configuration
All behaviour is controlled by `config.yaml` (see the generated template).
Environment variables override it:

| Env | Effect |
|---|---|
| `PORT` | HTTP port |
| `HOST` | Listen host |
| `DATABASE_PATH` | Path to the JSON database file |
| `JWT_SECRET` | Override `auth.jwtSecret` |

## Development

### Running without global install

```bash
# From the project root
npm install          # install deps (once)
npm start            # equivalent to: node bin/jrs.js run
npm run create       # equivalent to: node bin/jrs.js create <dir>
```

Or directly with Node:

```bash
node bin/jrs.js run
node bin/jrs.js create ./my-folder
```

### Tests

```bash
npm test                 # run node:test suite
npm run test:coverage    # with coverage report
```

### Typical development workflow

1. `npm run create ./my-project` — generates config, database and storage folder
2. `cd ./my-project`
3. `npm start` — starts the server, with hot-reload possible via `nodemon` (not included, but `node bin/jrs.js run` can be watched by external tools)
4. `npm test` — quick behaviour checks
5. `npm run build` — generates standalone binaries (Windows/macOS/Linux) via Node SEA

### Debugging

- Each request is logged by default as `[METHOD] /path -> status (duration)` on
  the console (e.g. `[GET] /products -> 200 (1ms)`), with no flag needed.
- Use `--debug` / `-d` for more detailed logs (auth, persistence, socket, errors).
- See `src/util/logger.js` to customize the log levels.

## Authentication

**Enabled by default** in the `config.yaml` generated by `create` (the `auth:`
block is pre-filled with a `jwtSecret`). You can disable it by commenting out
the `auth:` block — note that `POST /auth` will then return a clear error
instead of a token.

- `POST /auth` with `{email, password}` (or `+ admin: true` for `adm_users`)
  returns `{access_token, refresh_token, type}`.
- `PUT /auth/refresh` exchanges a refresh token (`nbf = jwtExpire`).
- `GET /me` returns the logged user without the `password` field.
- Protected routes require `Authorization: Bearer <token>`.
- `auth.urlSkip` and `urlUserPermission` control which routes need no token
  and which writes a regular user may perform. `enableAdm` restricts writes to admins.

> **Tip (Postman):** after enabling auth, run the *Login* request and copy the
> returned `access_token` into the collection `{{token}}` variable so the
> authenticated requests work.

## Pagination
Add `?page=` to a collection GET to receive
`{data, total, page, limit, totalPages}`. Without it, the raw array is returned.

## Building the standalone executable

The project generates a **self-contained binary** (Single Executable Application
via Node SEA) that runs without needing `node_modules` or the
`--experimental-sea-config` flag. It already embeds the entire Node runtime and
the server code bundled by `esbuild`.

```bash
npm install
npm run build
# outputs dist/json-rest-server(.exe)
```

### Binary usage tips

- **Where it lands:** `dist/json-rest-server` (`.exe` on Windows; no extension on
  macOS/Linux).
- **It is self-contained:** it can be copied to another machine that **does not**
  need Node.js installed nor the project dependencies. Just put `config.yaml`
  and `database.json` in a folder and run it.
- **Usage is identical to the Node CLI:** the same environment variables (`PORT`,
  `HOST`, `DATABASE_PATH`, `JWT_SECRET`) and flags (`run`, `create`, `--debug`)
  work on the binary.

```bash
# Copy the binary to an empty folder and initialize the project
./json-rest-server create
./json-rest-server run
```

- **Cross-platform build:** each operating system produces its own binary —
  run `npm run build` on Windows, macOS and Linux to get every version.
- **Automatic CI:** binaries for the three platforms are built automatically on
  tag push via `.github/workflows/build-sea.yml` and published as a *release*.
